サービス名は「NXTERA」（仮称）。英字1語で表記します。
※ フォルダ名・ファイル名の `Duo_` は制作チーム側の名称で、サービス名とは別物のため変更していません。

## 1. トーン&マナー

**「静か・実務・対等」**

読者は1〜3店舗のオーナーで、MEO代行やSNS運用代行で一度失敗している。
彼らが警戒するのは「うまい話の見た目」そのものなので、**広告らしさを削ることが最大の差別化**になります。

| 競合（MEO/SNS代行LP）の典型 | NXTERAの方針 |
|---|---|
| 純白背景＋青〜紫グラデーション | ウォームオフホワイト（紙）＋単色の墨緑 |
| 蛍光オレンジ／黄色の巨大CTA、点滅 | 単色ソリッドの1CTA。アニメーションなし |
| 「最大◯%削減」「導入◯◯店舗」 | 実績数値を一切出さない。出せるのは「込み」の約束と手順だけ |
| 絵文字見出し・全中央揃え・角丸カード乱用 | 左揃え基調、角丸は2/4/6pxの3段階、絵文字なし |
| キラキラの店舗イメージ写真 | 閉店後・手元・書類など「作業の時間帯」を撮る指示 |

地味になり過ぎないための担保は、**装飾ではなく情報密度**で取っています。
込み帯（伝票のような左罫＋タグ）、補助3点の罫線グリッド、PC右カラムの実物UI（トーク画面・資金繰り表・カレンダー）。
「もう手が動いている会社」に見えることが、派手さの代わりの信頼のつくり方です。

### 飲食と理美容の温度差
同じ型（要素の並び・余白・ボタン形状）を完全に共有したうえで、**アクセント色と余白の呼吸だけ**を変えています。

- 飲食：`#C1440E`（炭火・窯の赤茶）／背景をわずかに黄寄り。食欲と活気。
- 理美容：`#46707F`（くすんだ青灰）／背景をニュートラル寄り、上部余白を1段階広く、地の罫を薄く。清潔感と洗練。

### 書体
- 見出し：**Zen Kaku Gothic New 700**。字面が大きく角がわずかに丸い。ゴシックの強さを保ちつつ、断定的・威圧的に見えない。
- 本文：**Noto Sans JP 400/500**。小さめの級数・低照度でも読み負けない。
- フォールバック：`Hiragino Kaku Gothic ProN` → `Yu Gothic` → `Meiryo` → `sans-serif`。

### ロゴ（仮）
サービス名が英字1語になったため、旧案（カタカナ＋ラテン表記の2段組み）を解体しました。

- `.logo__type` に `NXTERA` を単独で置く。ウェイト700・**20px**・字間 **.11em**
- 2段目のラテン表記は不要になったため、`.logo__latin` は廃止
- マークは **軒（店）の輪郭＋その下に引かれた一本の線**。線だけがアクセント色なので、同じ形のままLPごとに色が変わります

- 375px幅ではロゴ横のディスクリプタ（「飲食店の経営支援」等）を非表示にし、サービス名を優先


### サイズ・余白・角丸
- 本文16px下限（`--fs-400`）。注記12pxは3行以上に使わない運用。
- 余白は4px単位（`--s-1`〜`--s-16`）。
- 角丸は2/4/6pxのみ。タップ領域は最小48px（`--tap`）、固定CTAバーは52px。

## 3. 構造（業種の切り替え方）

```html
<body data-domain="inshoku">   <!-- inshoku / biyo / kotehi / shikin / shindan -->
```

`tokens.css` の `body[data-domain="..."]` ブロックで `--c-accent` 系と背景のみを上書きしています。
**HTMLの構造とコンポーネントCSSは5枚で完全共通**なので、新しい業種を足す場合はトークンを1ブロック追加するだけで済みます。

コンポーネント（状態つき）：ヘッダー／ロゴ／FVグリッド／込み帯／ボタン（main・sub・ghost、hover/active/focus-visible/disabled）／補助3点リスト／ビジュアル枠（イラスト＋撮影指示）／イラスト共通クラス（`.il-*`）／担当者カード（`.who`）／支援の範囲（`.scope`）／資金繰り表＋山谷図（`.sheet` `.ch-*`）／固定CTAバー／診断の選択肢（hover/checked/focus）／カレンダーの枠（選べる／選択中／受付なし）。

**ページ内 `<style>` は原則置かない方針**にしました。02・04 のページ固有CSSはすべて `tokens.css` の「領域別の振れ幅」セクションに集約してあります（`body[data-domain="biyo"]` / `[data-domain="shikin"]` の上書き）。理由は2つで、(1) 同じ振れ幅を別ページで再利用できる、(2) LP側のファイルが確定コピーと構造だけになり、コピー差し替え時の事故が減るためです。例外は 03 の `.talk`（LINEトークのモック）だけで、これは固定費LP専用のためページ内に残しています。

## 4. ビジュアル（インラインSVG＋CSS）

画像ファイル・外部画像URL（ダミー画像サービス含む）は一切使っていません。オフラインでも全部描画されます。
絵柄は「線画＋面の塗り分け」。彩度は上げず、色は各LPのトークン（`--c-accent` 系）からのみ取っているので、
**同じ絵を別業種に置いてもトークンの差し替えだけで色が揃います**。

- **01 飲食**：閉店後のカウンター。奥にペンダントライトの灯りとボトル棚、壁の時計は22時すぎ。手元に伝票の束・スマホ・グラス・電卓。カウンター天板に `--c-accent-deep`（炭火の赤茶）を使い、灯りのにじみをアクセントの低透明度で作っています。
- **02 理美容**：セット面。大きな鏡に後ろ姿が映り、鏡上のライトバーがアクセント色。カウンターにボトル・コーム・はさみ、右にスタイリングチェア。垂直線を強調して清潔感を出しています。
- **03 固定費**：LINEトークの中に、**送られてきた請求書の写真サムネイル**をSVGで描画（内訳2行＋合計欄）。手で撮った1枚に見えるよう -1.2度の微傾きと影を付けています。
- **04 資金繰り**：**机をはさんで向かい合う2人**（担当者カード）と、**入金（実線）と支払い（破線）の山谷の折れ線**。4月で逆転する箇所に帯を立て、「支払いが入金を上回る月」とだけ記載。**金額は一切入れていません**。
- **05 診断・予約**：3領域バランス図をSVGに作り替え、比重の大きい順に①②③の番号と領域名を帯の中に入れ、上部に「比重 大 → 小」の目盛を追加。カレンダーは変更なし。

**線画は写真の代替**であり、本番では同じ構図の写真に差し替える前提です。そのため 01/02 は枠の下に撮影指示を残しています。要旨は **閉店後・手元・書類**。人物の顔と作り笑顔は使わず、広告写真ではなく記録写真の温度で撮ること。

表示の切り分け：**01 のビジュアル枠はPC（860px以上）のみ**（スマホは1行の撮影メモ）。**02 はスマホでも高さ104pxの帯で表示**します（`preserveAspectRatio="xMidYMid slice"` で中央帯をトリミング。美的判断で発注先を選ぶ層なので、絵を見せる方を優先）。**04 の担当者カードはスマホでも表示**します（人が最優先の領域のため）。

**縦位置を採用した理由**：撮影指示のキャプションを画面から外したことで、
右カラムが写真1枚だけになり下に縦の余白が溜まった。縦構図にすると
右カラムの高さが左の文字カラムに近づき、余白の振り分けが不要になる。

**理美容は明るい版を採用**：初版は全体が暗く、余白を広く線を細く取った理美容の
トーンに対して写真だけ重心が低かった。明るい版に差し替えたことで、
「閉店後」の空気は弱まったが、そこは補助3点の「サロンを閉めてからで間に合います」が
担保している。飲食が夜・暖色、理美容が昼・寒色という差は業種の実態に沿っており、
構図（手前に手元と道具、中ほど右に後ろ姿、奥へ抜ける）が共通なので
ブランドとしての同一性は保てている。

**空席を主役にしない**：「閉店後」を伝えているのは伝票と電卓（締め作業）であって
空席ではない。空席を大きく見せると「閉店後の静けさ」ではなく「客が来ていない店」に読め、
集客に悩む読者に対して責めているように見える。採用画像は空席が見えてはいるが、
主題は右側の店主と手元にある。

枠の比率は画像に合わせている（`.shot__img` の既定は3:2、飲食のみ
`body[data-domain="inshoku"]` で 2:3 に上書き）。
右カラムは440px（1120px以上で500px）、縦は中央揃え。

横位置版の原本（1536×1024 PNG）は縦位置版で上書きされたため残っていない。
書き出し済みの `-wide` / `-tight` の2ファイルだけが残る。

この画像は **AI生成の仮画像**。本番は同構図で撮影する前提。
画面には「仮画像」のラベルも撮影指示も出していない（提案の場で見せるため、
制作上のメモは画面から外した）。**撮影指示の原文は `画像生成プロンプト.md` に残してある。**

## 4-3. 集客LPから診断を外した理由（01）

01 の主CTAを「3分診断」から「相談スケジュールを選ぶ」に変え、代わりにFVの下へ
**「よくある失敗」セクション**を置いた。

- **診断の中身が集客LPと噛み合っていなかった。** 5問は業種／月商／家賃／販促費／資金繰り感で、
  これは3領域の横断診断。「飲食店 集客」で来た人が家賃と資金繰りを聞かれることになる
- **集客は診断と構造的に相性が悪い。** 固定費は請求書1枚で金額が出るが、集客は診断しても
  出てくるものが定性的。正確に診るには口コミ数や予約経路など、オーナーが手元に持っていない
  データが要る
- **この層はすでに自覚している。** 席が埋まっていないことは本人が一番分かっており、
  気づかせる必要がない。必要なのは「なぜ今までのやり方が効かなかったのか」の説明

共感だけで終わると競合の「よくあるお悩み」と同じになるため、
**症状（何が起きたか）と、その理由（なぜそうなるか）を必ず対で書く**構成にした。
この「なぜ」の一行が、代行で失敗した層に対する「分かっている会社」の証明になる。

**固定費LP・資金繰りLPでは診断は有効**なので、集客だけ外す非対称で問題ない。

### 01 は集客に振り切る（他領域に言及しない）

当初は締めの一文で3領域横断へ橋を架けていたが、**01では固定費・資金繰りに
一切触れない**方針に変更した。流入クエリが「飲食店 集客」である以上、
LPの約束を集客1本に絞ったほうが強い。

削除・変更したのは4箇所。

| 箇所 | 変更前 | 変更後 |
|---|---|---|
| ロゴ副題 | 飲食店の経営支援 | 飲食店の**集客**支援 |
| アイブロウ | 集客・固定費・資金繰りを1社で | 飲食店の集客を、1社で通して |
| 補助3点 | 集客・固定費・資金繰りを横断して見ます | 施策ごとに業者を分けません。マップも口コミもSNSも同じ担当が見ます |
| 締めの一文 | 集客だけを見ていると気づけません／3領域を横断 | 施策を単体で見ていると気づけません／順位・投稿・掲載を予約と再来までつなげる |

### 「できること」は、失敗に1対1で答える

失敗セクションの直後に `#shien` を置き、**4つの失敗それぞれに対応する支援**を並べた。
各カードの末尾に「→ 『順位は上がったのに、再来しない』に効きます」という一行を入れ、
前のセクションを明示的に回収している。支援を単に列挙するより、
直前に読んだ痛みと紐づくぶん納得が速い。

| できること | 答えている失敗 |
|---|---|
| Googleマップと口コミを、来店後まで設計する | 順位は上がったのに、再来しない |
| 予約までの道を、1〜2タップに縮める | 投稿は増えたのに、予約が増えない |
| 媒体費を、1人あたり残る額で判断する | 客数は増えたのに、残るお金は減った |
| 1年分の集客カレンダーをつくる | 止めた2ヶ月後に、予約が落ちた |

1件目の本文で**特典の「口コミ収集ツール」がどこで使われるか**に触れ、
FVの特典帯と支援の中身を繋いでいる。特典が浮かないようにするため。

CTAは失敗セクションから外し、**できることの末尾に1つだけ**置いた。
地色は `.sec--alt` で交互に変え、2セクションの境目を作っている。

**「1社で通して見る」という訴求自体は残している。** 対象を3領域から
「集客の中の複数施策」に付け替えただけで、分断された施策を1社でまとめるという
構図は同じ。3領域横断は統合トップや業種別LPで見せる。

## 4-2. 領域ごとの重心の作り分け

骨格（CTAの3入口・固定CTAバー・トークン・回遊のための操作感）は5枚で共通のまま、**感情の温度だけを振り分け**ています。

| LP | 読者の感情 | FVの重心 | 具体的な差 |
|---|---|---|---|
| 01 飲食集客 | 攻め・もっと稼ぎたい | 情景と可能性 | 情景イラスト（閉店後のカウンター）。変更なし |
| 02 理美容集客 | 美的判断で選ぶ | 絵に面積を渡す | 文字を削り、PCのビジュアル幅を380→440/520pxに拡大。SPでも帯で表示。線を細く（1.7→1.25）、余白を一段広く、地の罫を薄く（.22） |
| 03 固定費 | 損してるかも・すぐ効く | 1アクションに絞る | 視線を「キャッチ→込み帯→送るボタン」の3点に。トークは往復2通、請求書は内訳2行、主CTAを56→62px・18→20pxに強化。アイブロウ・撮影メモ・注釈を削除 |
| 04 資金繰り | 不安・人に言いにくい | 絵より「人」 | キャッチ直後に担当者カード（氏名は仮名／肩書は「店舗支援担当」）。**支援の範囲**を条件・CTAより上に独立パネル化。数字（資金繰り表）は人より下・PCでは右カラムを190px下げて配置。斜光をオフにして装飾を一段落とす |

**肩書について**：資格名（税理士・中小企業診断士など）は未取得のため一切使用していません。`.who__role` は「店舗支援担当」のみ。氏名「佐野 直人」は仮名で、README仮値一覧に記載しています。

## 4-4. 統合版（06）— 01と02を1枚にまとめた別案

**01・02の置き換えではなく、比較検討用のもう1案。** 3枚とも残してある。

### 構成
FV（業種共通）→ 業種タブ →〔よくある失敗／できること〕→ CTA。
**切り替わるのはタブから下だけ**で、FVとCTAは共通。

### 1枚にまとめるときの問題と、その処理

| 問題 | 処理 |
|---|---|
| 業種を両方向けに書くとFVがぼやける | キャッチを「予約が入らない理由、見えていますか。」に。**飲食もサロンも予約商売**なので、具体性を落とさずに両方へ届く |
| どちらの業種向けか一目で分からない | FV右カラムに**2業種の写真を並べる**。文字で説明せず、絵で示す |
| 失敗事例は業種で全く違う | タブで切り替え。飲食4件・理美容4件をそのまま持ち込み、内容は01・02と同一 |
| アクセント色をどちらに寄せるか | **どちらにも寄せない。** ブランドの墨緑で通す（`data-domain="tougou"`）。業種色は01・02が持つ |

### タブの実装
素のJavaScript（ライブラリなし）。`role="tablist"/"tab"/"tabpanel"`、
`aria-selected`、左右矢印キーでの移動に対応。非表示は `hidden` 属性で行う。

### 結論：LPは分割（01・02）で進める

比較した結果、**広告の着地としては分割版を採用**する。
決め手は、差別化しているコンテンツが**100%業種固有**であること。
失敗4件もできること4件も、飲食と理美容で1つも共通していない。
共通なのはFV・CTA・特典だけで、中身が全部違うのに器だけ共有している状態になる。
広告を①一般クエリ ②飲食 ③理美容で出し分ける設計とも噛み合わない。

### ただし06は残す：統合トップへの転用

**06のFVは、統合トップの設計としてはむしろ正解。**
指名検索・紹介・名刺から来た人の受け皿には「飲食もサロンも両方やる会社だ」と
示すページが要る。06の

- 業種に寄せないキャッチ（予約が入らない理由、見えていますか。）
- 2業種の写真を並置して、文字で説明せず絵で示す
- アクセントを業種色ではなくブランドの墨緑で通す

はそのままトップに使える。LPとしては分割に負けるが、トップとしては勝つ。

### 01・02と比べるときの観点
- **広告の流入と噛み合うか。** 「飲食店 集客」で来た人に、タブを選ばせる一手間が増える
- **FVの具体性は落ちていないか。** 業種特化の「その空席、来月もそのままにしますか。」ほどの刺さり方はしない
- **運用は軽くなる。** 1枚なので更新も広告の出稿先も一本化できる

## 4-5. 予約カレンダーを診断から分離した理由

もとは1ファイルに診断と予約を並べていたが、**実装でも別ページにする**方針にして
`05-shindan.html` と `07-yoyaku.html` に分けた。

1. **予約への入口が3つある** — 診断経由／各LPのCTA直行／固定バー。
   **直行組のほうが多数派になる**ため、予約が診断の下にぶら下がっていると、
   予約したいだけの人が診断画面を通過させられる
2. **URLが必要** — 広告やLINE配信から予約ページへ直接送れる
3. **計測が分離できる** — 診断完了率と予約率は別のKPI
4. **予約カレンダーは外部埋め込みの想定**（TimeRex等）。診断のJSと同居させない

診断結果からは「結果を引き継いで予約ページへ遷移」でよく、
別ページのほうが引き継ぎの設計が素直になる。

### あわせてカレンダーを作り直し
受付が 8:00〜翌1:00 になったのに、カレンダーは日中が全て「×」で夜だけ空いている
旧仕様のままで、LPの表記と矛盾していた。**8:00から30分刻み**に作り直した。

- 行は **8:00 〜 翌0:30 の34行**。相談が30分なので最終開始は0:30（終了が1:00）
- **区分けはしない。** 日中と営業後を分ける見出し行は入れず、8:00から翌0:30まで
  1つの表として連続させている。時間帯を区切ると「夜は特別な枠」に見えてしまうが、
  実際は全部が同じ相談枠で、オーナーは自分の空き時間を探すだけでよい
- 行数が増えるぶんセルを詰めた（`.cal--fine`。高さ40px→30px、級数も一段下げ）
- 空き状況はダミー。約7割を「空」にしてある

## 4-6. 固定費LP（03）— LINE前提をやめた

主CTAが「LINEで請求書を1枚送る」で、FV右カラムもLINEのトーク画面だったが、
**LINEが配信専用（1:1の受信をしない）ため、この導線が成立しない。**
受け取り手段が未確定のまま進めるため、次の判断で組み直した。

- **主CTAは01・02と同じ「相談スケジュールを選ぶ」に統一。**
  差別化の本体は「LINE」ではなく **「請求書1枚でいい」**（競合は12ヶ月分の明細を要求）
  だったので、受け取り手段が変わっても価値は落ちない
- 「請求書1枚」は補助3点に残し、**相談の準備が軽いという約束**として機能させた
- 受け取り手段が決まったら、CTAまわりに一行足すだけで済む形にしてある

### 右カラムは「診断できる費目の一覧」に
LINEのトーク画面が使えなくなったため、**費目一覧**に差し替えた。
調査では費目を一覧で見せている競合がほとんどなく、意思決定に直結するのに
空いている要素だった。**金額や削減率の目安は載せていない**（実績がないため）。

### 表現の制約（サイト上で守っているもの）
- 賃料は「交渉」と書かない。**資料づくりと論点の整理まで**（弁護士法72条）。
  貸主と話すのはオーナー自身である旨を明記
- 電力は「切替代行」と書かない。**診断と比較情報の提供まで**
- できることセクションの末尾で、この線引きを明示している
